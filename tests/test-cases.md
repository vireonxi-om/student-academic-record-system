## How the tests work

* **Integration tests (this table).** Each case feeds a fixed script of keystrokes to `student_pbl --echo` and checks the transcript.
  A case also fails if the exit code is not 0 or anything is written to stderr. The full transcript of every case is in `tests/transcripts/`.
* **Unit tests.** `tests/unit_tests.c` (`make unit`) checks the calculation, validation, search, storage and entry functions directly.
* **Expected values** come from the hand-calculated dataset in `docs/proposal.md` (S001-S005), not from the program's output.
* **Categories:** Normal, Boundary and Invalid cases as required by the project brief. Cases for the optional enhancements are named *Enhancement*.

## Consistency checks covered

* Every occupied marks row belongs to the matching student (TC02, TC06, TC23, TC40).
* The record count never exceeds 100 (TC18) and a rejected or cancelled entry never changes it (TC23 and the unit tests; TC27 covers cancellation by end of input).
* Frequency counts in every row add up to the number of students (TC08, TC19).
* Pass count + fail count equals the number of students (TC09, TC10, TC35).
* Searching never modifies stored data (TC03-TC05, TC39; unit tests).
